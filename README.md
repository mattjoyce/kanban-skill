# kanban-ai

A Markdown-based Kanban board plugin for [Claude Code](https://claude.com/claude-code).

Cards live as `.md` files in a **central, shared cards repo** — one card per file, namespaced per project. The board is derived at read-time — no database, no server. Status is tracked in YAML frontmatter, and the repo is synced over git so multiple agents and workspaces share one ticket stack.

## Install

Requires Claude Code **v1.0.33+** (`claude --version` to check).

### From a marketplace

If this plugin is available in a marketplace you've added:

```
/plugin install kanban@marketplace-name
```

### From a local clone

Clone the repo and load it directly during development or personal use:

```bash
git clone https://github.com/mattjoyce/kanban-skill.git
claude --plugin-dir ./kanban-skill
```

You can also load multiple plugins at once:

```bash
claude --plugin-dir ./kanban-skill --plugin-dir ./other-plugin
```

### Verify installation

Once loaded, run `/help` inside Claude Code. You should see `kanban:kanban-ai` listed. The skill is model-invoked, so Claude will use it automatically when you discuss tasks or kanban boards.

## Usage

The skill is model-invoked — Claude will use it automatically when you ask about tasks, cards, or your kanban board. You can also trigger it explicitly:

```
> create a new kanban card for implementing user auth
> show me the board
> move card 3 to doing
> what cards are blocked?
```

## Shared setup (central cards repo)

Cards do **not** live in each project repo — they live in one shared cards repo cloned at `$KANBAN_BASE` (e.g. `~/kanban`), whose `origin` is a bare git repo on the NAS. Every host and agent pulls/pushes the same stack.

1. Bootstrap once (creates the bare repo on the NAS and your local clone):
   ```bash
   bash setup.sh /Volumes/Projects/kanban.git ~/kanban
   ```
   (Adjust the NAS path per host — Linux hosts mount it elsewhere.)
2. Export `KANBAN_BASE` in your shell profile:
   ```bash
   export KANBAN_BASE="$HOME/kanban"
   ```

Each project's cards land at `$KANBAN_BASE/<project-slug>/cards`, where `<project-slug>` is derived from the repo's git **remote URL** (see `project_slug.sh`) — so two clones of the same repo share one namespace.

## Card Fields

| Field        | Required | Description                                                                 |
|--------------|----------|-----------------------------------------------------------------------------|
| `id`         | Yes      | Short collision-safe id (4-char base36, e.g. `a3k9`). Generated by `new_id.sh`, not max+1. |
| `status`     | Yes      | `backlog` · `todo` · `doing` · `done` (archive is a folder, not a status)    |
| `priority`   | No       | `High` or `Normal` (default)                                                |
| `blocked_by` | No       | List of card IDs that must be `done` first. e.g. `[2, 5]`                   |
| `assignee`   | No       | Who owns the card                                                           |
| `due_date`   | No       | Target date (YYYY-MM-DD)                                                    |
| `tags`       | No       | List of labels                                                              |

## Example Card

`kanban/setup-ci.md`:

```markdown
---
id: 7wu
status: todo
priority: High
blocked_by: [a3k9, c1m2]
tags: [devops]
---

# Set Up CI Pipeline

Configure GitHub Actions for automated testing.
```

## Rules

- A card cannot move to `doing` until all cards in its `blocked_by` list are `done`.
- IDs are short random base36 strings generated by `new_id.sh` and checked for collisions — never sequential, so concurrent agents don't clash.
- Cards maintain a `## Narrative` section — a durable log of decisions, discoveries, and outcomes.

## Bundled Scripts

The plugin includes helper scripts for board operations. Claude uses these automatically, but you can also run them directly:

| Script              | Purpose                                          |
|---------------------|--------------------------------------------------|
| `view_board.sh`     | Display board grouped by status                  |
| `ready.sh`          | List cards ready to start (unblocked todo/backlog) |
| `board_all.sh`      | Cross-project summary across `KANBAN_BASE`       |
| `search_by_tag.sh`  | Find cards by tag                                |
| `search_content.sh` | Full-text search across cards                    |
| `show_blocked.sh`   | List blocked cards and their blockers            |
| `list_tags.sh`      | Show tag usage with counts                       |
| `list_all_cards.sh` | Pipe-delimited dump of every card                |
| `new_id.sh`         | Generate a collision-safe card id (internal)     |
| `project_slug.sh`   | Derive project slug from git remote (internal)   |

Scripts are located at `skills/kanban-ai/scripts/` within the plugin directory.
